# 房间平面图


执行具体方法前读取 [Craft 场景命令与参数](references/craft-methods.md)，按其中的对象选择、会话、输入替换和结果检查执行。

## 任务起点

先读取素材，确认交付用途、目标尺寸或时长、修改范围与必要格式。能从任务和素材确定的细节直接采用合理默认值；只询问会改变结果的缺失条件。

需要可见编辑器时交给 **cadcraft-editor** 技能。独立安装：`npx skills add full-aigc-skills/cadcraft-skills --skill cadcraft-editor`。当前新增技能为本地候选，发布前使用本地配套插件，不把此安装命令当作已发布证明。

## 执行步骤

1. 确定单位、墙厚和尺寸来源，先建立墙体、门窗、标注图层。
2. 按实际尺寸绘制墙线，在门洞处断开墙段；示例明确提供门扇与开启弧，窗洞和墙厚需按确认尺寸另建。
3. 添加开门方向及固定设施，尺寸标注使用统一基准。
4. 布置图框和比例，另存工程并输出阅读图。

## 工具落地

用 open/new_drawing 打开或新建，query_entities 核对几何；execute 执行命令，save 保存，render 预览。

先读取实际工具 schema，再填写参数；对象或文档 ID 使用返回值。查询到的命令必须在当前后端可用。保存前选择新输出路径，保留输入。需要的算法、格式或命令不存在时说明缺口，不能用相近名称冒充。

## 结果检查

- 检查墙线连接与门洞实际开口，门洞不得被闭合矩形封住；核对宽高原生标注与实体量测一致。
- 用实体查询核对关键长度，不只看截图。
- 标出未知尺寸；不将示意图声称为施工图。

对照用户目标检查实际内容，而不只检查进程退出码。局部编辑查看局部细节，版式任务查看整页，时间媒体查看起止与关键段。异常结果先检查当前工程，避免重复执行不可逆操作。

## 交付

返回可编辑工程、实际派生文件和简短说明：做了哪些修改、哪些步骤因当前能力未执行、需要用户判断的内容。只列真实存在且已经检查的文件。若用户随后返工，读取本次源工程并局部修改，保留已接受的内容。

## 按实际尺寸生成新房间计划

使用本技能自带 `scripts/room_plan.py`，输入字段见[毫米尺寸示例](assets/example-input.json)。width、depth为房间宽深；door_start为底边左端到门铰链距离，door_width为开口和门扇宽，label为保留原文的房间名。门朝房间内开启90度。

```bash
python3 <本技能目录>/scripts/room_plan.py --input room.json --output plan.json
```

只生成新图计划，不修改现有图。拒绝非有限数、布尔尺寸、越界开口、门扇超出房深、空标签和换行标签；输出采用独占创建。墙线按门洞分段，门扇、开启弧、文字和标注分层；尺寸取实际端点，不覆盖数值。只是单线空间示意，不包含墙厚、窗户、设备或施工设计。

CLI用argv执行 `cadcraft-cli run --metric`，将每步作为一个 `--cmd` 参数，内容为命令名、空格、JSON参数，最后 `--save <新路径.dxf>`。同画面MCP先确认使用新图，再在同一编辑器会话按实际execute schema逐步调用；独立CLI不会自动更新已打开的编辑器。重开DXF检查实体、门洞和原生尺寸，再渲染检查文字及标注。已有工程不能直接套用该新图计划。

## 已观察到的宿主边界

当前已验证CLI能正确保存中文房间名，但已验证的增强0.7.0内嵌界面会把“会议室”的“议”显示为缺字；不能因为保存值正确就验收中文外观，也不能擅自替换成拼音。该界面实时inspect中的原生尺寸measurement曾返回0，而画面与保存DXF重开量测为6000/3500；须结合实体端点或保存重开量测，不以缓存字段单独判断尺寸。两项问题均未由本计划生成器修复。
